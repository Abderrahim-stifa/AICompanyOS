## نبذة عن المشروع

AICompanyOS تطبيق محلي لإدارة عمليات شركة صغيرة من لوحة عربية موحدة. يعتمد Python وStreamlit وSQLite، ويضم إدارة العملاء والمشاريع والمهام والحسابات، وسجل النشاط والتدقيق، والنسخ الاحتياطي، ومسارات عمل لوكلاء متخصصين.

المشروع يعمل محلياً ولا يحتاج إلى مفتاح API لتشغيل الوظائف الحالية. لا يعني ذلك أن الوكلاء الحاليين نماذج ذكاء اصطناعي توليدية؛ تفاصيل ذلك موضحة أدناه.

## المزايا الحالية

- لوحة تحكم وصفحات مستقلة عبر Streamlit navigation.
- إدارة العملاء والمشاريع والمهام، مع روابط اختيارية موثوقة بين المهمة والعميل والمشروع.
- تصنيف محلي للمهام واقتراح الأولوية والوكيل المناسب.
- فصل وكلاء Pipeline الخمسة عن وكلاء الأدوار السبعة.
- مركز للوكلاء السبعة يعرض خططاً منظمة حسب الدور.
- سجل تشغيل خطط الوكلاء، مع موافقة بشرية أو رفض قبل تسجيل النتيجة.
- فواتير عربية RTL بصيغة HTML قابلة للطباعة أو الحفظ PDF من المتصفح.
- دفتر دخل ومصروفات مع إنشاء وتعديل وحذف القيود، وسجل تدقيق للقيم السابقة والجديدة.
- فواتير محفوظة بحالات مسودة وصادرة ومدفوعة جزئياً أو بالكامل، مع إصدار مسجل بالتدقيق.
- تسجيل دفعات جزئية أو نهائية مع مرجع فريد اختياري، ومنع تكرار المرجع أو تجاوز الرصيد، وربط كل دفعة تلقائياً بقيد دخل.
- إلغاء الفواتير غير المدفوعة مع سبب مسجل، وإرجاع مبالغ الدفعات جزئياً أو كلياً بقيد مصروف عكسي وسجل تدقيق؛ القيود الناتجة عن الدفعات والإرجاعات محمية من التعديل والحذف اليدوي.
- سجل أنشطة وسجل تدقيق للعمليات المدعومة.
- تسجيل دخول أساسي بحساب مشترك واحد لكل نشر.
- نسخ احتياطي تلقائي دوري، وواجهة لتحسين/ضغط قاعدة SQLite.
- واجهة عربية RTL وسمة داكنة.
- سطر أوامر وواجهة JSON API محلية.

## الوكلاء والذكاء الاصطناعي

يوجد مساران منفصلان:

1. **Pipeline agents:** خمسة مكونات لتصنيف المهام والبحث والإدارة والتنفيذ والمحاسبة.
2. **Role agents:** سبعة أدوار أعمال: CEO وResearch وConsultant وEngineer وMarketing وAccountant وMarket Analyst.

محرك تصنيف المهام الحالي يعتمد على مطابقة الكلمات المفتاحية وقواعد محلية. كما أن خطط الوكلاء السبعة الحالية deterministic وقائمة على قوالب/قواعد محلية، وليست نماذج LLM مستقلة. موافقة المستخدم مطلوبة قبل اعتماد خطة التشغيل، والنتيجة النهائية تُسجّل يدوياً؛ لا يوجد تنفيذ خارجي ذاتي أو اتصال فعّال بمزود LLM في الوضع الحالي.

## الفواتير والمالية

يمكن توليد فاتورة HTML عربية لمهمة وعرضها للطباعة أو استخدام خيار Save as PDF في المتصفح. يتم تهريب القيم الديناميكية والتحقق من المبلغ قبل إدراجها في المستند. لا يتضمن هذا المسار مولّد PDF خادمياً.

تدعم الصفحة المالية الآن إنشاء مسودات فواتير من المهام وإصدارها وتسجيل دفعات جزئية أو نهائية. تُحفظ بيانات المهمة والعميل والمبلغ كنسخة داخل الفاتورة، ويُسجل كل دفع في جدول المدفوعات وقيد دخل مرتبط ضمن معاملة SQLite واحدة. مرجع الدفع اختياري وفريد عند إدخاله، ويُرفض الدفع المكرر أو الذي يتجاوز الرصيد. تدعم المنظومة أيضاً إلغاء الفواتير غير المدفوعة، وإرجاع الدفعات جزئياً أو كلياً مع إنشاء قيد مصروف عكسي وتحديث صافي التحصيل. لا يمكن إلغاء فاتورة عليها دفعات مسجلة، ويجب تسجيل الإرجاع أولاً. ما زالت الضرائب، التسويات البنكية، والترقيم/القوالب القانونية المحلية خارج النطاق؛ لذلك لا يمثل هذا نظاماً محاسبياً متكاملاً.

## التشغيل على Windows

يتطلب Python 3.10 أو أحدث:

```bat
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

أو شغّل `run_windows.bat` من جذر المستودع. ثم افتح http://localhost:8501.

ملاحظة: هذا المستودع يشغّل `app.py`. إذا كانت لديك نسخة محلية مستقلة تعتمد على `ai_console.py` و`ai_company.py`، فلا تستبدل ملفاتها بهذه النسخة قبل مراجعة الاختلافات ودمجها بعناية.

## المصادقة والأمان

تظهر شاشة تسجيل الدخول قبل تحميل صفحات التطبيق. يجب ضبط بيانات الدخول خارج المستودع.

باستخدام متغيرات البيئة:

```bat
set AICOS_AUTH_USERNAME=operator
set AICOS_AUTH_PASSWORD=ضع-كلمة-مرور-قوية-هنا
python -m streamlit run app.py
```

أو عبر `.streamlit/secrets.toml`:

```toml
[auth]
username = "operator"
password = "ضع-كلمة-مرور-قوية-هنا"
```

لا ترفع ملف الأسرار إلى GitHub. المصادقة الحالية حساب واحد مشترك لكل نشر؛ لا توفر إدارة حسابات متعددة أو RBAC أو تحديد معدل محاولات الدخول. لا تعتبرها وحدها حاجزاً أمنياً كافياً لنشر عام. استخدم HTTPS وضوابط نشر مناسبة قبل إتاحة التطبيق خارج جهاز موثوق.

واجهة API المحلية تعمل على `127.0.0.1:8000`. يتطلب الربط بعنوان عام تعيين `AICOS_API_KEY`، ويرفض الخادم الربط العام دون مفتاح.

## قاعدة البيانات والنسخ الاحتياطي

تُهيّأ قاعدة SQLite تلقائياً عند تشغيل التطبيق، ويمكن تنفيذ التهيئة عبر:

```bash
python -m core.init_db
```

تُستخدم migrations إضافية للحفاظ على الجداول والبيانات القائمة. يتضمن التطبيق نسخاً احتياطياً تلقائياً عند بدء التشغيل وفق الفاصل المحدد، كما تتوفر وظيفة VACUUM لتحسين قاعدة البيانات. احتفظ بنسخ احتياطية مستقلة قبل أي صيانة أو ترقية مهمة.

## الحالة الحالية وخارطة الطريق

الإصدار المعرّف في التطبيق هو **v0.5.0**. هذا وصف لحالة الكود، وليس ادعاءً بأن كل عناصر خارطة الطريق أدناه مكتملة.

| المجال | الحالة |
|---|---|
| إدارة المهام والعملاء والمشاريع | CRUD أساسي وروابط اختيارية بمفاتيح خارجية؛ الترحيل يحافظ على المهام القديمة والحذف يفصل الرابط دون حذف المهمة |
| سجل التدقيق | يسجل عمليات CRUD المدعومة للمهام والعملاء والمشاريع والقيود المالية مع لقطات قبل/بعد؛ لا يغطي بعد دورة محاسبية متكاملة |
| الوكلاء | خطط محلية مع سجل وموافقة بشرية؛ تكامل LLM وتنفيذ الأدوات ما زالا مستقبليين |
| المالية | دفتر دخل ومصروفات مع CRUD وتدقيق؛ فواتير ومدفوعات جزئية/كلية وإلغاء الفواتير غير المدفوعة وإرجاع الدفعات مع قيود عكسية محمية؛ التسويات والضرائب تحتاج تطويراً |
| المصادقة | حساب مشترك واحد؛ تعدد المستخدمين وRBAC والحماية من محاولات الدخول المتكررة غير متاحة |
| الواجهة | بنية متعددة الصفحات وهوية داكنة؛ توحيد التفاصيل البصرية لكل الصفحات ما زال مطلوباً |

### مراحل التطوير المقترحة

1. ✅ ربط المهام بالعملاء والمشاريع بمفاتيح خارجية وترحيلات SQLite آمنة.
2. ✅ إضافة سجلات فواتير محفوظة وإصدارها مع تدقيق انتقال الحالة.
3. ✅ تسجيل الدفعات الجزئية والكلية وربطها بقيود الدخل ومنع التكرار وتجاوز الرصيد.
4. ✅ إلغاء الفواتير غير المدفوعة وإرجاع المدفوعات مع قيود عكسية وسجل تدقيق.
5. استكمال التسويات البنكية والضرائب.
6. إضافة مزود LLM اختياري بإعدادات آمنة وموافقة بشرية وحدود تنفيذ.
7. إضافة إدارة مستخدمين وصلاحيات بعد تصميم نموذج أمني مناسب.
8. استكمال توحيد الواجهة واختبارات التكامل والاستعادة من النسخ الاحتياطية.
