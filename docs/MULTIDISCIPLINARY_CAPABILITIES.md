# القدرات متعددة التخصصات في AICompanyOS

## الرؤية

يتطور AICompanyOS ليجمع إدارة الشركة مع تحليل الطلبات وتخطيط الأعمال وإنتاج المخرجات عبر مجالات متعددة. الهدف هو تحويل الطلب من وصف أولي إلى نطاق واضح وخطة ومخرجات قابلة للمراجعة والاختبار، مع بقاء القرارات الحساسة تحت إشراف المستخدم.

## المجالات

| المجال | أمثلة على المخرجات |
|---|---|
| هندسة البرمجيات | المتطلبات، البنية التقنية، الكود، الاختبارات، التوثيق والصيانة |
| التصميم البصري وتصميم المنتجات | موجز التصميم، UI/UX، الهوية البصرية، النماذج الأولية ومواصفات التصميم |
| التصورات المعمارية | البرنامج الوظيفي والمساحي، بدائل التوزيع، التصورات الأولية وملاحظات المراجعة |
| دراسات الجدوى | تحليل السوق، افتراضات التكاليف والإيرادات، نقطة التعادل، السيناريوهات والمخاطر |
| البحث وحل المشكلات | تعريف المشكلة، جمع الأدلة، تحليل الأسباب، مقارنة البدائل وخطة الاختبار |
| إدارة الأعمال | العملاء، المشاريع، المهام، الفواتير، العمليات المالية والتقارير |

## ما هو مطبق في هذه المرحلة؟

توفر `core/capabilities.py` كتالوجاً منظماً للمجالات، وموجهاً أولياً يطابق كلمات عربية وإنجليزية لتحديد مجال أو أكثر والوكلاء المقترحين. التوجيه الحالي حتمي ومحلي (Rule-based / Offline)، وليس نموذج LLM ولا بحثاً مباشراً ولا تنفيذاً مستقلاً.

عند عدم وجود تطابق، يعيد الموجه حالة مراجعة عامة بدلاً من تخمين تخصص. ويمكن لكل مجال أن يطابق حتى ثلاثة مجالات ذات صلة، مع اقتراح وكلاء الأدوار المتاحة حالياً.

## ضوابط المخرجات

- افصل الحقائق الموثقة عن الافتراضات والتقديرات.
- لا تعرض خطة أو قالباً على أنه منتج تم تنفيذه.
- لا تعتمد تكاليف أو إيرادات تقديرية كقيود مالية فعلية.
- لا تنشر كوداً أو تصميماً قبل الاختبار والمراجعة.
- التصورات المعمارية أولية ولا تعوض المخططات التنفيذية أو اعتماد مهندس/معماري مؤهل وفق القوانين المحلية.
- تتطلب التوصيات الاستثمارية بيانات سوق وفرضيات واضحة وتحليلاً للحساسية والمخاطر.
- يجب طلب موافقة بشرية قبل الإجراءات الخارجية أو المالية أو التي يصعب التراجع عنها.

## مراحل التطوير التالية

1. ربط الموجه بواجهة استقبال الطلبات وصفحة الوكلاء.
2. إنشاء قوالب خطط مفصلة لكل مجال مع الافتراضات والمخاطر ومعايير القبول.
3. إضافة سجل للمخرجات والملفات والإصدارات وربطها بالمشاريع والمهام.
4. إضافة موصلات اختيارية للبحث ومزودي النماذج مع حفظ المفاتيح خارج المستودع.
5. توفير مسارات إنتاج واختبار متخصصة للبرمجيات والتصميم ودراسات الجدوى.
6. قياس جودة المخرجات، وتسجيل موافقات المستخدم ونتائج المراجعة.

هذه المراحل ليست كلها منفذة في الإصدار الحالي؛ يجب تتبع كل مرحلة عبر تغييرات واختبارات مستقلة.
